# Quick Task 260726-26d: Make post-deploy smoke target the stable public Scholar Scout Vercel production domain

## Goal

Make production-success smoke checks probe Scholar Scout's stable public Production domain without weakening Vercel deployment protection or losing evidence about the deployment that triggered the check.

## Tasks

### 1. Separate the public smoke target from deployment-event evidence

**Files:**

- `.github/workflows/post-deploy-smoke.yml`
- `scripts/test-production-tooling.mjs`

**Action:** Change the smoke job's `SCHOLARSCOUT_SMOKE_BASE_URL` binding to the established `SCHOLARSCOUT_SMOKE_BASE_URL` GitHub Actions secret, rather than the repository-dispatch deployment URL. Keep the production-environment guard, existing health/auth/adaptor secret bindings, Corepack/frozen install, JSON report and artifact handling, and no-rollback incident behavior. Preserve the dispatch URL for concurrency grouping and the incident's Deployment URL field, and preserve `github.event.client_payload.git.sha` for the deployed-commit checkout and incident evidence; these values identify the event but must not become the smoke request target. Add a focused Node test that reads the workflow contract and proves the smoke target uses the configured secret while the dispatched URL and deployed SHA remain present as evidence inputs. Do not change `scripts/production-smoke.mjs`, remove Vercel Standard Protection, print secrets/cookies, or add an access-bypass token.

**Verify:**

<verify>
  <automated>pnpm run test:production-tooling</automated>
</verify>

**Done:** A production dispatch tests the stable configured public domain, and the workflow continues to retain event-specific URL/SHA evidence, report artifacts, and the existing protected-production safeguards.

### 2. Document the stable production-domain configuration contract

**Files:**

- `docs/vercel-deployment.md`

**Action:** Extend the protected-production deployment guidance to explain that Vercel Standard Protection may redirect protected dynamic deployment URLs to SSO, so post-deploy smoke uses the GitHub Actions `SCHOLARSCOUT_SMOKE_BASE_URL` repository secret as its documented target. Specify the current stable public Production value `https://scholar-scout-web.vercel.app/`, require maintainers to update that configuration point before an intentional production-domain change, and distinguish it from the dispatch URL retained as incident/deployment evidence. Keep the existing protected-`main`, Vercel dashboard, Corepack, frozen-install, and human rollback guidance intact; do not place credentials, cookies, private deployment URLs, or production data in the documentation.

**Verify:**

  <automated>node -e "const fs=require('node:fs'); const workflow=fs.readFileSync('.github/workflows/post-deploy-smoke.yml','utf8'); const docs=fs.readFileSync('docs/vercel-deployment.md','utf8'); if (!workflow.includes('SCHOLARSCOUT_SMOKE_BASE_URL: ${{ secrets.SCHOLARSCOUT_SMOKE_BASE_URL }}') || !workflow.includes('github.event.client_payload.git.sha') || !workflow.includes('const deploymentUrl = context.payload.client_payload.url;') || !docs.includes('https://scholar-scout-web.vercel.app/')) process.exit(1)"</automated>

**Done:** The deployment runbook explains the public stable-domain smoke target, its maintainable GitHub configuration point, and why dispatch deployment URLs remain evidence only under Vercel protection.
