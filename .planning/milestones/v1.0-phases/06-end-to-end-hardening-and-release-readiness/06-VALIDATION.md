## Phase gate

The candidate-quality lane must record a successful immutable `pnpm install --frozen-lockfile --ignore-scripts`, then successful `pnpm test`, `pnpm run lint`, `pnpm run typecheck`, and `pnpm run build`, all tied to the candidate. Before either Preview lane begins, the rehearsal must execute Plan 06-04's high-risk API/webhook/persistence suite and Plan 06-03's owned temporary-process browser tracer; each execution must emit a distinct candidate-bound scrubbed record containing commit, UTC, command or ordered suite-command list, pass/fail result, and safe error category. Fail-closed aggregation consumes those records before the same tracer against an isolated protected Preview and the distinct blocking Preview outage proof can satisfy D-09. Each external runner must use its unique opaque capability only to invoke the fixed no-body lifecycle transport inside the adapter-owning runtime; browser/evidence never receive the capability. That runtime must create/read/clean deterministic generated non-personal programme records through `saveProgrammeRecord`, `getGovernedProgrammes`, and `deleteProgrammeRecord`, prove discovery and recommendation use without ranking snapshots, deny production/browser/source-selected input, and perform exact cleanup after success, test failure, crash, and signal without raw JSON/Blob access. A missing, failed, unexecuted, or candidate-mismatched candidate-quality command, high-risk, local-browser, protected Preview-browser, or Preview-outage evidence is a release-gate failure. Per D-10, the release record retains candidate-quality plus distinct high-risk, local-browser, protected Preview-browser, and Preview-outage/restoration outcomes and their approved artifact/deployment identifiers or links where applicable; real production evidence remains separately governed by the production runbook.
