<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel Git integration to repository dispatch | A third-party deployment event provides environment and deployment URL to a GitHub workflow. |
| Smoke workflow to production endpoints | The workflow receives secrets and probes production health/data-status routes. |
| Failed-smoke workflow to GitHub Issues | Failure evidence becomes a maintainer-visible public-to-repository incident artifact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Elevation of privilege | post-deploy-smoke.yml dispatch handler | high | mitigate | Accept only Vercel success dispatches and guard the smoke job on the production environment before loading production smoke secrets. |
| T-01-07 | Information disclosure | smoke incident issue | high | mitigate | Limit issue content to URL, SHA, workflow/artifact links, and runbook link; never serialize credentials, cookies, environment values, or exported data. |
| T-01-08 | Tampering / Availability | rollback response | medium | mitigate | Alert maintainers and link the data-safe human incident procedure; no automated deployment reversal is authorized. |
| T-01-SC | Tampering | deployment dependency installation | high | mitigate | Vercel uses the Corepack-selected pnpm pin and frozen lockfile with lifecycle scripts disabled. |
</threat_model>
