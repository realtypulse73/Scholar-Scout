# Make Phase 6 Rehearsals Simple, Isolated, and Repeatable

## Objective

Replace temporary branches, manually copied environment values, and shared Preview storage with two permanent, isolated Vercel rehearsal projects: a normal baseline and a controlled community-outage lane.

## Work

1. Upgrade the project, portable tooling, workflows, and Vercel build contract to Node 24.
2. Make rehearsal fixture paths code-owned as `scholarscout/rehearsal/<fixture-id>/data.json`, and allow lifecycle routes only for Vercel Preview rehearsal mode.
3. Configure separate baseline and outage Preview projects, private Blob stores, fixture identities, non-production authentication secrets, and separate project-scoped Vercel discovery tokens.
4. Discover candidate-matched ready Vercel deployments automatically with the Vercel CLI filtered by each project's Git commit metadata; remove temporary ref, URL, cleanup-record, and handoff-file inputs.
5. Run candidate quality, focused isolation, tooling, typecheck, lint, and Vercel-equivalent build checks; then run the first PR-head rehearsal.

## Safety boundary

The rehearsal projects have Preview-only data and credentials. They do not use the primary Scholar Scout project’s storage, OAuth credentials, custom domain, or production variables.
