> Visual and interaction contract for the bright, hopeful Scholar Scout visual system. Generated by gsd-ui-researcher and verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — retain the established custom Tailwind CSS design system and reusable `components/ui` primitives |
| Preset | not applicable |
| Component library | none — use the existing `Button`, `Card`, `Badge`, and `Input` primitives |
| Icon library | none — do not add one for this presentation-only phase |
| Font | Space Grotesk everywhere: navigation, headings, body, labels, controls, and data displays; system sans-serif fallback |

### Identity mark

Use one code-native `ScholarScoutBrandMark` React component in public/student identity locations. It combines an inline scalable SVG academic/pathway motif with the visible `Scholar Scout` Space Grotesk wordmark. The SVG uses scholar red, white, and light silver, with no heavy black outline or detailed shield. The SVG is decorative when the visible wordmark supplies the accessible name; identity links retain a clear `Scholar Scout` accessible name. Support compact and full display sizes without substituting a raster image.

The PostCSS build explicitly loads `apps/web/tailwind.config.js`. That file is the runtime Tailwind source of truth; keep `tailwind.config.ts` semantically identical because it is the typed reference used by the codebase. Do not introduce shadcn or a third-party component registry in this phase.

## Typography

Use exactly these four visual scales. Use only regular and semibold weights; replace visual-only `font-bold` and `font-extrabold` emphasis with semibold where this phase touches a component.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 | 1.35 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | `clamp(24px, 5vw, 40px)` | 600 | 1.1 |

Use Space Grotesk with normal letter spacing for body and controls. Uppercase metadata may use `0.06em` tracking, but no other text may use expanded tracking. Display is one fluid token, bounded by the already-declared Heading and Display scales; body text never drops below 16px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Primary page backgrounds, cards, form fields, and readable content surfaces |
| Secondary (30%) | `#F3F5F7` | Silver page bands, navigation, subdued panels, and neutral hover surfaces |
| Accent (10%) | `#C8102E` | Primary CTA fills, selected states, active navigation indicators, focus rings, and small forward-progress details only |
| Destructive | `#B4233C` | Delete, remove, irreversible moderation, and destructive confirmations only |

Supporting tokens: blush highlight `#FFF1F3`; hover/pressed red `#A30E26`; silver border `#D7DEE6`; deep blue-gray text and high-contrast border `#26364A`; muted readable copy `#516173`; success remains green, warning remains amber, and danger keeps its destructive semantic meaning.

Accent reserved for: primary buttons, selected filters/options, the active route marker, focused controls, small progress indicators, and scene journey details. Red must not be a large reading background, body-text color, default card fill, or replacement for success/warning/destructive meaning. Do not introduce black or charcoal page backgrounds; replace existing dark full-width sections and dark shells with white or silver surfaces while retaining contrast.

Every text/control pairing must meet WCAG 2.1 AA contrast: 4.5:1 for normal text, 3:1 for large text and non-text focus/boundary indicators. Primary red buttons use white text; body copy uses deep blue-gray, not red.

## Motion and Scene Contract

The current `scholar-scout-transition-v1.png` remains the still base for the home, school-locker, and peer-community lifestyle scenes. Do not replace it or add a generic video background. Build one reusable scene wrapper/treatment rather than duplicating scene styles in each route.

- Civilian-side imagery remains still. Motion is clipped to the student half of people-based lifestyle scenes and is `aria-hidden`; it never moves text, controls, cards, or navigation.
- The student half may have one walking-student layer plus one contextual journey detail (a passing train/bus or a soft light trail). Limit a scene to two animated layers total; no flashing, bouncing, parallax-on-scroll, audio, or autoplay video.
- Use CSS `transform` and `opacity` animation only. A journey layer takes 10–12 seconds per loop with `ease-in-out`; a secondary light trail takes 8–10 seconds at low opacity. The visible shift stays within 24px and starts automatically.
- At `prefers-reduced-motion: reduce`, disable every scene animation and render only the unchanged still image. Do not add a motion toggle because the approved behavior is automatic with device-level accessibility protection.
- Reserve a stable silver fallback surface and a fixed scene min-height before the background image loads or if it is unavailable. Foreground content stays legible over a white-to-silver overlay; the active student-side motion must never pass beneath actionable text.
- On screens below 768px, retain the right-hand student-side clip and slow motion but reduce animated-layer opacity by half. Preserve the full 44px control targets and make scene copy wrap naturally above it rather than clipping or shrinking controls.
