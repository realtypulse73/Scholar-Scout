## Shared Patterns

### Import and component conventions

**Sources:** `apps/web/components/ui/Card.tsx` lines 1-16; `apps/web/components/simulations/SimulationScene.tsx` lines 1-91.

- Use `@/` imports and `import type` for prop/domain types.
- Default-export one focused React component per PascalCase file.
- Use two-space indentation, single quotes, semicolons, and Tailwind utility strings.
- Keep visual wrappers server-safe unless browser state is genuinely required.

### Accessibility and motion safety

**Sources:** `apps/web/components/simulations/SimulationScene.tsx` lines 27-40; `apps/web/components/ui/Button.tsx` lines 33-42; approved `07.1-UI-SPEC.md`.

```tsx
<div className="absolute inset-0 opacity-30" aria-hidden="true">...</div>
<div className="relative z-10 flex h-full flex-col justify-between">...</div>
```

Apply `aria-hidden` and `pointer-events-none` to decorative scene layers; retain an explicit above-layer content stack. Maintain `focus-visible:ring-*`, minimum touch targets, natural text wrapping, and CSS-only `prefers-reduced-motion` animation removal.

### Semantic color handling

**Sources:** `apps/web/components/ui/Button.tsx` lines 12-18; `apps/web/components/ui/Badge.tsx` lines 10-16; `apps/web/components/ui/Input.tsx` lines 15-25.

Brand is a primary/selected/focus accent. `success`, `warning`, and `danger` remain semantic state scales. Invalid input stays `danger`; it is not made brand red. Use the Tailwind token role first, then alter direct utility classes only where they encode the outdated blue/dark visual identity.

### Error handling and data boundaries

**Sources:** `apps/web/components/peer-community/PeerCommunity.tsx` lines 20-45; `apps/web/app/schools/[slug]/page.tsx` lines 9-32.

No presentation change may weaken existing client error state, server `notFound()` behavior, governed-programme read, or API mutation path. Keep visual changes around existing content rather than moving business logic into the new scene component.
