## Implementation Decisions

### App-wide typeface
- **D-01:** Use Space Grotesk as the app-wide typeface direction. Apply it consistently to headings, body copy, navigation, controls, and the existing pages rather than limiting it to a new landing screen. The founder selected it after reviewing Space Grotesk, Sora, and an Orbitron/Sora combination.

### Red, white, and silver visual balance
- **D-02:** Use a light, hopeful white-and-silver foundation across pages and cards. Do not introduce black or charcoal page backgrounds.
- **D-03:** Use bright red for primary actions and selected states, with soft blush-red highlights for warmth. Red is an accent rather than a dominant reading background, so the student-oriented experience remains optimistic rather than warning-like.
- **D-04:** Use a deep blue-gray only where necessary for readable text, borders, and accessible contrast; it must not read as a dark theme.

### Student-side scene motion
- **D-05:** On lifestyle scenes that depict people, keep the civilian half visually still and give the student half subtle, slow, looping movement.
- **D-06:** Motion may combine walking students with contextual journey details such as a passing train/bus or a soft moving light trail. It should enrich the scene without distracting from copy, controls, or accessibility.
- **D-07:** Start scene motion automatically, but honor `prefers-reduced-motion` by rendering a still version for visitors who request less motion.

### the agent's Discretion
- Define exact token values, animation durations, easing, responsive behavior, and which existing people-based scenes receive which approved motion motif.
- Preserve readable contrast for all text and interactive controls; use existing app content and routes rather than inventing new marketing claims.

## Summary

This is a presentation-only migration that should retain the current Next.js, React, Tailwind, and custom UI-primitive foundation. The source already centralizes the two global seams required for a broad visual change: `apps/web/app/layout.tsx` owns the app font variable, while `apps/web/tailwind.config.js` is the active Tailwind runtime configuration and `tailwind.config.ts` is its typed mirror. The existing blue `brand` and `ink` vocabulary appears in 65 TSX files, so the plan must update shared tokens and primitives first, then repair the few hard-coded blue/black/slate surfaces that token replacement will not reach. [VERIFIED: codebase grep]

The existing still scene asset is already shared by the home page, school-locker page, and peer-community page. Implement one reusable scene wrapper that owns the still image, a clipped right-hand decorative layer, and its reduced-motion fallback; do not add a video, a per-page animation implementation, or new data behavior. The home and school-locker pages already use `.transition-story`; `PeerCommunity` currently recreates a separate inline background, which is the clearest duplication seam to remove. [VERIFIED: codebase grep]

**Primary recommendation:** Use `next/font/google` for Space Grotesk, replace the design tokens and UI primitives coherently, then introduce a CSS-only `StudentJourneyScene` wrapper whose decorative student-side layers are disabled in `prefers-reduced-motion: reduce`.

### Pattern 1: Root-owned, build-time font variable

**What:** Replace the local Geist sans assignment in `app/layout.tsx` with `Space_Grotesk` from `next/font/google`, expose it as a CSS variable, and make the Tailwind `sans` family consume that variable. Keep the existing mono font only if an existing code/data display requires it. [VERIFIED: codebase `apps/web/app/layout.tsx`, `apps/web/tailwind.config.ts`]

**When to use:** Apply once at the root for a true app-wide font migration; do not import Space Grotesk independently in page components. [CITED: https://nextjs.org/docs/app/api-reference/components/font]

**Example:**

```typescript
// Source: https://nextjs.org/docs/app/api-reference/components/font
import { Space_Grotesk } from 'next/font/google';

const spaceGrotesk = Space_Grotesk({
  subsets: ['latin'],
  display: 'swap',
  variable: '--font-space-grotesk',
});

// Add spaceGrotesk.variable to the root html/body class list.
```

### Pattern 2: Semantic token migration before route cleanup

**What:** Define the approved palette as semantic `brand`, `ink`, surface, border, and focus values in both Tailwind config files; update UI primitives to establish the primary/secondary/destructive hierarchy; then update exceptional hard-coded blue, slate, and black classes by meaning, not with a blind search-and-replace. [VERIFIED: approved `07.1-UI-SPEC.md`, codebase `apps/web/components/ui/*`]

**When to use:** The old `brand` scale is blue and `ink` is slate, while 65 TSX files use those tokens or direct dark/blue utility classes. A primitive-first migration limits diff size and prevents red from accidentally replacing success/warning/destructive meanings. [VERIFIED: codebase grep]

**Example:**

```typescript
// Use semantic role, not a color-name utility, in a shared primitive.
const variants = {
  primary: 'border-brand-600 bg-brand-600 text-white hover:bg-brand-700',
  secondary: 'border-ink-300 bg-white text-ink-800 hover:border-brand-500',
  danger: 'border-danger-600 bg-danger-600 text-white hover:bg-danger-700',
};
```

### Pattern 3: CSS-only, clipped decorative scene treatment

**What:** Create one server-safe wrapper that renders the existing background still, a content slot, and `aria-hidden` decorative layers inside a right-half clipping container. The civilian side remains only the static image; the student side receives at most one journey element and one low-opacity light-trail element. [VERIFIED: approved `07.1-UI-SPEC.md`]

**When to use:** Replace the home/school `.transition-story` section and the separate `PeerCommunity` inline background with the same wrapper. Do not put animation classes on text, controls, or page layout containers. [VERIFIED: codebase `apps/web/app/page.tsx`, `apps/web/app/schools/[slug]/page.tsx`, `apps/web/components/peer-community/PeerCommunity.tsx`]

**Example:**

```css
/* Source: MDN prefers-reduced-motion documentation; values are locked by UI-SPEC. */
.student-journey-layer {
  animation: student-journey 11s ease-in-out infinite;
}

@media (prefers-reduced-motion: reduce) {
  .student-journey-layer,
  .student-light-trail {
    animation: none;
  }
}
```

### Pattern 4: Contrast-proven role pairs

**What:** Treat each foreground/background/state pairing as a named visual contract. The approved primary red `#C8102E` against white calculates to 5.88:1; pressed red `#A30E26` against white to 7.93:1; deep blue-gray `#26364A` against white to 12.29:1; and muted copy `#516173` against white to 6.35:1. The pale silver border `#D7DEE6` against white is only 1.36:1 and therefore must not be the sole required focus/interactive boundary. [VERIFIED: local WCAG contrast calculation]

**When to use:** Verify all component states, especially red focus rings on white/silver and light borders on white cards. Normal text needs 4.5:1; large text and required non-text/focus indicators need 3:1. [CITED: https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum] [CITED: https://www.w3.org/WAI/WCAG21/understanding/non-text-contrast.html]

### Anti-Patterns to Avoid

- **Blind token renaming:** Do not map every blue/ink class to red. Success, warning, and destructive states retain their own semantic colors; dark simulation panels need a light/silver redesign rather than a red replacement. [VERIFIED: approved `07.1-UI-SPEC.md`, codebase `apps/web/components/simulation*`]
- **Text over variable image areas without a fixed overlay:** A photo can lower local contrast unpredictably. Maintain the white-to-silver overlay and test the least legible area. [CITED: https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum]
- **Animating layout or foreground content:** Do not animate width, height, margins, text, cards, controls, or navigation. Restrict animation to transformed/opacity-only, clipped, `aria-hidden` decoration. [VERIFIED: approved `07.1-UI-SPEC.md`]
- **Per-route motion CSS:** Do not add inline animation strings on home, school, and peer pages. One wrapper prevents behavioral drift. [VERIFIED: codebase grep]
- **A JavaScript motion preference toggle:** The approved choice is automatic motion with device-level reduction, not a new persisted user preference or control. [VERIFIED: approved `07.1-UI-SPEC.md`]

## Common Pitfalls

### Pitfall 1: Updating only the TypeScript Tailwind config

**What goes wrong:** The source-of-record mismatch leaves production builds on old blue/Geist utilities.  
**Why it happens:** `globals.css` explicitly loads `tailwind.config.js`; `tailwind.config.ts` is a typed mirror, not the runtime config. [VERIFIED: codebase `apps/web/app/globals.css`, `apps/web/tailwind.config.js`, approved `07.1-UI-SPEC.md`]  
**How to avoid:** Change both files in the same task and add a verification check that their token maps remain semantically identical.  
**Warning signs:** A class in source appears correct but the production build still renders the prior palette/font family. [VERIFIED: codebase configuration]

### Pitfall 2: Breaking meaning by treating red as every positive state

**What goes wrong:** Success, warning, destructive, selection, and primary actions become visually indistinguishable.  
**Why it happens:** The existing `brand` palette is blue and is used broadly; a mechanical replacement changes semantic meanings. [VERIFIED: codebase `apps/web/components/ui/Badge.tsx`, `apps/web/components/ui/Button.tsx`]  
**How to avoid:** Redesign only `brand` as the primary/action scale, preserve `success`, `warning`, and `danger`, and inspect all direct blue/slate/black classes by component purpose.  
**Warning signs:** A delete button, success badge, and primary CTA all use the same red family. [VERIFIED: approved `07.1-UI-SPEC.md`]

### Pitfall 3: Reduced-motion CSS that still leaves transitions moving

**What goes wrong:** Decorative scene elements still drift or fade for a visitor requesting reduced motion.  
**Why it happens:** A reduced rule targets one class but omits a secondary layer, delayed animation, or transition.  
**How to avoid:** Give every decorative moving element a shared scene class and reset each animation in one later `@media (prefers-reduced-motion: reduce)` block. [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion]  
**Warning signs:** Browser devtools emulation shows any computed animation name other than `none` in reduced-motion mode.

### Pitfall 4: Decorative layer affects interaction or reading order

**What goes wrong:** The motion overlay captures pointer events, becomes an accessibility-tree distraction, or appears below/over text on a narrow view.  
**Why it happens:** Absolute decoration is placed in the content layer rather than in an isolated visual wrapper.  
**How to avoid:** Set decoration to `aria-hidden`, `pointer-events: none`, clipped student-side containment, and a lower stacking context than content. Preserve layout/min-height independently. [VERIFIED: approved `07.1-UI-SPEC.md`]  
**Warning signs:** Keyboard focus is obscured, clicking an action fails, or a horizontal scrollbar appears at small widths.

### Pitfall 5: Treating pale silver as a sufficient focus ring

**What goes wrong:** Focus or state boundaries disappear against white.  
**Why it happens:** The approved silver border token is intentionally subtle and measures 1.36:1 against white. [VERIFIED: local WCAG contrast calculation]  
**How to avoid:** Keep a strong red or deep-blue-gray focus ring/offset pair that reaches 3:1 against adjacent colors. [CITED: https://www.w3.org/WAI/WCAG21/understanding/non-text-contrast.html]  
**Warning signs:** A keyboard user cannot find a focused white button/card on a white or silver surface.
