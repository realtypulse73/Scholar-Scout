<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| browser direct-upload payload to Vercel signer | Upload ID, revision, file kind, and pathname are attacker-controlled until re-authorized against private state. |
| trusted account session to private contributor state | The session actor must exactly own the active invitation and Draft package before a token can be minted. |
| signed PUT token to private Blob store | The short-lived token may write only the exact server-owned path and allowed content constraints. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-13.2-23 | E | direct-upload token signer | high | mitigate | Re-authorize trusted account ownership, active invitation, Draft lifecycle, package ID, and exact revision immediately before signing. |
| T-13.2-24 | T | client upload payload | high | mitigate | Parse a strict opaque ID/kind/revision contract, compare it with current server state, and keep server-owned path/limits authoritative. |
| T-13.2-25 | I | token and callback payload | high | mitigate | Return only opaque capability fields, retain private paths and rights records server-side, and cover response shape in route tests. |
| T-13.2-26 | R | contributor lifecycle | medium | mitigate | Preserve current conditional mutation/revision conflict behavior; refused capability requests do not mutate private submission state. |
| T-13.2-27 | E | Preview owner exception | high | mitigate | Leave D-14 server-only runtime/identity/capability gates and ordinary reviewer/publisher separation untouched. |
</threat_model>
