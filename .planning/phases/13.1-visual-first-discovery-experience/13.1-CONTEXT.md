# Phase 13.1: Visual-First Discovery Experience — Context

**Gathered:** 2026-09-27
**Revised:** 2026-09-28 — media-free release selected
**Status:** Ready for replanning

<domain>
## Phase Boundary

Make catalogue discovery visually compelling by default without weakening student agency, factual clarity, motion accessibility, or privacy. Students encounter a calm, code-native visual arrival when discovery begins and a restrained catalogue atmosphere across browse surfaces. Governed facts, source links, comparison, and official next actions remain clear and separate. This is a presentation-only phase: it adds no media asset, external renderer, user upload, student-data collection, inference, analytics signal, ranking signal, or persistence path.
</domain>

<decisions>
## Implementation Decisions

### Media-free visual-first arrival
- **D-01:** Discovery opens with an automatic **Visual welcome** before the factual catalogue. It is not an optional explorer, sign-in step, Story prerequisite, personal-input prompt, or ordering input. — **Reversibility:** costly — this is the first-arrival composition across catalogue discovery and responsive/UAT expectations.
- **D-02:** The welcome is made only of code-native HTML/CSS and existing app primitives. It is abstract, non-provider-specific, and does not render, request, select, or depend on an image, video, iframe, embed, external URL, generated raster, or local asset file.
- **D-03:** The welcome leads by an in-page action into source-first cards. Do not place provider facts, source state, save/compare, or official actions in the abstract visual region, and do not characterize its visual motifs as a real provider/campus scene.

### Calm catalogue-wide atmosphere
- **D-04:** Apply restrained, CSS-only red/white/silver depth across the `/programmes` overview and focused detail shells. Decorative layers must be catalogue-scoped, static for this release, `aria-hidden`, pointer-inert, behind readable content, and width-safe.
- **D-05:** Respect reduced-motion preferences with the same static presentation. Do not add a new autoplay or looping visual path. The prior narrow centred-card media exception remains unchanged and dormant unless its existing reviewed-local conditions already apply; this phase does not use, expand, or re-approve it.

### Privacy and release independence
- **D-06:** Showing reviewed school/programme information does not require collecting student information. Do not add sign-in gating, consent prompts, event tracking, passive engagement capture, profile changes, ranking inputs, provider changes, or store/API changes.
- **D-07:** Supersede the former local illustration/video fixture plan and its Phase 13 UAT bridge. Phase 13 browser verification remains independently outstanding and must not be marked complete, implied complete, or used as a release dependency for this media-free phase.

### the agent's Discretion
- Choose abstract code-native motifs, copy, layout, and CSS intensity, provided they remain calm, readable, static, non-provider-specific, source-first, and accessibility-safe.
- Reuse existing catalogue layout, reviewed snapshot, source/action, semantic control, focus treatment, and responsive primitives. Do not create an alternate discovery data path or change `renderableMedia` projection.

### Superseded Decisions
- **D-03 through D-05 of the 2026-09-27 context** (illustration fallback, media hierarchy, and local UAT fixtures) are superseded by D-02 and D-07 above. No asset right, provenance, or fixture is needed for the first release.

### Folded Todos
- **Make discovery visual-first** — replace the conditional optional explorer with a default code-native first impression while keeping source-first school information and student choice intact.
</decisions>

- `CatalogueDiscoveryOverview` already owns the normal-flow catalogue composition; the conditional explorer can be replaced without changing the reviewed model.

- The existing `DiscoveryPreviewSlot` renderer is deliberately narrow for approved local media. It is a preserved boundary, not a dependency for this phase's welcome.

### Integration points
- Evolve the catalogue overview and focus/detail shells to make the visual arrival core and media-free.
- Add component/CSS assertions for automatic arrival, no-media rendering, unchanged factual controls, static decoration, reduced-motion state, and responsive accessibility.

<specifics>
## Specific Ideas

- The first impression should feel like an inviting, practical starting point: it catches attention, then directs the student immediately to real school/programme information.
- Abstract spatial motifs can suggest possibility without representing Buffalo, Houston, Chicago, a campus, a provider, or a student.
- The catalogue should feel alive through hierarchy, color, light, and depth—not through video, a media feed, or data capture.
</specifics>

<deferred>
## Deferred Ideas

- Student recruitment, research, uploads, testimonials, or peer content require a separate consent, age/privacy, moderation, rights, takedown, attribution, retention, and governance phase.
- Provider/campus photographs, video, Maps/Street View, and other third-party renderers require a separate rights, terms, privacy, accessibility, and provenance decision.
- A visual system that changes the whole application outside catalogue discovery is a later design phase.
- Phase 13 browser UAT remains separate historical work and cannot be satisfied by this phase.
</deferred>
