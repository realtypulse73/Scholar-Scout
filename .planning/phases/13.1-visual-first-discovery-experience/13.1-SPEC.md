# Phase 13.1: Visual-First Discovery Experience — Specification

**Created:** 2026-09-28
**Revised:** 2026-09-28 — media-free release selected
**Ambiguity score:** 0.07 (gate: ≤ 0.20)
**Requirements:** 7 locked

## Goal

`/programmes` changes from an optional media explorer into an automatic, media-free visual welcome and a source-first catalogue atmosphere, without collecting student information, altering discovery choice, or adding media rights dependencies.

## Background

`CatalogueDiscoveryOverview` currently shows an “Optional visual explorer” only when reviewed items have `renderableMedia`. The reviewed snapshot, factual cards, filters, source links, comparison, and official actions already work without that media. `CatalogueFocusView` has a scoped decorative seam, but its existing treatment is not the planned shared visual-first experience. The previous plan depended on local illustration/video assets and a Phase 13 UAT bridge; the product decision is now to ship the first visual experience without any media assets or data-collection work.

## Requirements

1. **VIS-01 Automatic visual welcome**: Every reviewed `/programmes` render includes one normal-flow, media-free welcome before the filters and factual results.
   - Current: The visual entry is conditional on `visualItems.length` and is labelled optional.
   - Target: A code-native welcome appears for signed-out and signed-in visitors, including empty/no-media snapshots, without depending on Stories, personal input, profile state, ordering, or `renderableMedia`.
   - Acceptance: Component tests prove exactly one welcome precedes filters/results for media-bearing and no-media models, and it contains no provider-specific factual record, source state, save/compare action, or official-provider action.

2. **VIS-02 Media-free visual language**: The welcome and catalogue atmosphere use only HTML, CSS, and inline/vector-capable code-native primitives already shipped with the application.
   - Current: The potential visual flow is built around `DiscoveryPreviewSlot` media branches and there is no always-present media-free visual composition.
   - Target: The new visual-first composition does not add, select, request, or render bitmap, video, iframe, embed, remote URL, provider imagery, generated raster asset, or asset-provenance fixture.
   - Acceptance: Focused component/source-contract tests show the new welcome/atmosphere render without `DiscoveryPreviewSlot`, `<img>`, `<video>`, iframe, external asset URL, or a new `public/images`/`public/media` dependency.

3. **VIS-03 Source-first school information**: Visual presentation leads into, but never replaces or decorates as fact, the governed reviewed programme information.
   - Current: Factual cards already preserve source state, date, verification links, comparison, and official actions; the optional explorer creates a separate visual entry point.
   - Target: The welcome offers an in-page route to the factual catalogue while existing cards and detail views retain their exact reviewed facts, sources, status language, comparison, and official verification actions.
   - Acceptance: Regression tests prove programme count, filters, normal/qualification ordering, all-visible empty states, source links, comparison, and official actions are unchanged by visual state.

4. **VIS-04 Scoped calm atmosphere**: Overview and focus/detail shells receive a restrained, code-native red/white/silver visual depth that remains behind a readable content plane.
   - Current: The overview has no shared visual shell and the focus decoration is a single existing seam.
   - Target: Decorative nodes are scoped to catalogue routes, `aria-hidden`, pointer-inert, width-safe, and static in the media-free release.
   - Acceptance: DOM/CSS contract tests assert the catalogue-only shell, hidden/pointer-inert decoration, readable content plane, and overflow-safe responsive classes; visual UAT at 320px, 768px, and desktop reports no horizontal overflow.

5. **VIS-05 Motion and media boundary**: The release adds no autoplay or newly looping media and respects reduced-motion preferences.
   - Current: Phase 13 contains a narrow existing centred-card local-media controller, while this phase has no completed arrival implementation.
   - Target: The media-free welcome has no playback path or time-based visual loop; non-essential decorative movement is absent under reduced motion, and the existing centred-card exception is neither widened nor newly invoked by the welcome.
   - Acceptance: Tests prove the new welcome contains no playable media and no `play()` path; reduced-motion contract tests retain a static visual state; existing centred-card pause/visibility/reduced-motion tests remain green.

6. **VIS-06 Accessible responsive first impression**: The visual welcome and atmosphere remain understandable, keyboard-safe, and readable at phone, tablet, and desktop widths.
   - Current: Existing catalogue components have semantic controls and focused Jest coverage, but not the required always-present welcome.
   - Target: The welcome has a semantic heading and an in-page factual-discovery action; decorations are absent from the accessibility tree; long copy and zero/one/many catalogue states retain readable, non-clipped factual controls.
   - Acceptance: Held-out component tests cover no-media, empty, long-text, and repeated-render states; browser UAT confirms keyboard navigation, 320px/768px/desktop reflow, and reduced-motion readability.

7. **VIS-07 Privacy and release independence**: Phase 13.1 remains presentation-only and does not turn the visual first experience into a student-data collection or Phase 13 verification mechanism.
   - Current: The catalogue is already browseable without sign-in, while the former 13.1 plan coupled release to an unrelated Phase 13 media-fixture/UAT bridge.
   - Target: No profile fields, consent prompt, sign-in requirement, analytics event, ranking signal, persistence change, provider data change, or student research workflow is added; Phase 13’s outstanding UAT remains independently tracked.
   - Acceptance: Plan/file review shows only catalogue presentation, CSS, and focused tests change; no API, server store, account/profile, ranking, candidate, or public asset file is modified; Phase 13 is not marked verified by Phase 13.1 evidence.

## Boundaries

**In scope:**
- One automatic media-free welcome before `/programmes` filters/results.
- Code-native catalogue-only atmosphere and responsive presentation refinements.
- Preservation tests for reviewed factual records, source actions, choice controls, media boundary, and reduced motion.
- Manual accessibility/responsive verification of the changed catalogue route.

**Out of scope:**
- Bitmap, video, remote, provider-specific, copied, generated, or third-party visual media — the release must not need asset rights, provenance, or a media fixture.
- New student-data collection, consent prompts, research workflows, analytics, profiling, or persistence — those require a separate privacy and product phase.
- Changes to provider records, publication, ranking, qualification ordering, sign-in, comparison, official links, or source governance — this is presentation-only.
- Closing, altering, or relying on Phase 13 browser UAT — it is independently tracked historical work.
- Whole-application redesign, Maps/Street View, embeds, and new UI packages — unnecessary for the bounded catalogue experience.

## Constraints

Retain Next.js, React, TypeScript, Tailwind, and Jest with no new packages, API routes, persistence fields, public media files, external requests, or browser-side candidate data. Use the reviewed snapshot only for factual content; do not modify its resolver or use `renderableMedia` to drive the new welcome. Maintain the existing constrained centre-card media behavior without expanding it.

## Acceptance Criteria

- [ ] Every reviewed `/programmes` model renders one media-free visual welcome before filters and results, including a no-media/empty state.
- [ ] The new visual-first composition uses no image/video/iframe/embed/remote-asset renderer, no `public/images` or `public/media` addition, and no `DiscoveryPreviewSlot` welcome dependency.
- [ ] Factual cards preserve reviewed source/status/date, filters, all-visible ordering, comparison, and official verification actions.
- [ ] Catalogue-only decorative layers are static, `aria-hidden`, pointer-inert, behind readable content, and width-safe at 320px through desktop.
- [ ] The welcome adds no playback, loop, timer-driven visual behavior, or widened media exception; reduced-motion presentation remains static.
- [ ] Keyboard and long-text/no-result states preserve visible, reachable factual controls.
- [ ] No student-data collection, sign-in gate, analytics signal, ranking/profile/store/API/provider-data/public-asset change, or Phase 13 verification claim is introduced.
