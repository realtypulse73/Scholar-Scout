# Phase 13.1 — Media-Free UI Design Contract

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing custom Tailwind design system; no new component-system initialization |
| Components | Existing native React/Tailwind controls and `components/ui` primitives |
| Font | Existing Space Grotesk stack and system fallback |
| Visual material | Code-native HTML/CSS and inline/vector-capable primitives only; no bitmap, video, iframe, embed, or remote asset |

Extend existing `background`, `silver`, `blush`, `ink`, `brand`, `focus`, and `warning` tokens. Retain the 8px `rounded-card`, `min-h-touch` (44px), `focus:ring-focus`, `min-w-0`, and responsive reflow patterns. Do not add a parallel token system, asset pipeline, animation package, or visual provider.

## Phase Boundary and Non-Negotiables

- `/programmes` always begins with one **Visual welcome**, before the filters and reviewed results; it is not optional, a Story destination, a sign-in step, or a personal-data prompt.
- The visual welcome is abstract and non-provider-specific. It cannot portray, name, or imply a real campus, school, student, provider affiliation, official photograph, or source-backed fact.
- The visual layer contains only its heading, descriptive copy, and an in-page action to factual discovery. It does not contain programme cards, source state, provider facts, save/compare controls, or official-provider links.
- The visual layer uses no `DiscoveryPreviewSlot`, `renderableMedia`, `<img>`, `<video>`, `<iframe>`, external URL, public image/video asset, playback control, timer, or loop.
- Existing cards and focus/detail remain the factual surfaces: source/status/date, comparison, save, and official verification actions are preserved exactly.
- Decorative layers are catalogue-scoped, static, `aria-hidden`, pointer-inert, behind a solid readable content plane, and overflow-clipped only at their local shell.
- `prefers-reduced-motion` preserves the same static visual state. This phase does not alter, invoke, or widen the existing narrow centred-card media exception.
- No new data collection, consent, telemetry, profile state, ranking signal, store/API change, or Phase 13 UAT claim is permitted.

## Information Hierarchy

```text
1. Catalogue route identity — “Reviewed opportunity catalogue”
2. Visual welcome — abstract invitation + “Browse reviewed opportunities” anchor
3. Student-controlled filters and ordering — unchanged
4. Reviewed factual result cards — source/status/date, compare/save, official verification
5. Detail view — facts and sources before optional related choice actions
```

The welcome is the first visual moment, not the factual authority. The next meaningful interaction is an in-page route to reviewed opportunities.

## Layout Contracts

### `/programmes` overview

- Wrap the route in a `catalogue-visual-shell` with `min-w-0`, `max-w-full`, and local `overflow-x-clip` protection.
- Render one `catalogue-visual-welcome` before the existing grid. Its readable panel stays in normal flow; its decorative red/silver planes are sibling/child nodes marked `aria-hidden="true"` and `pointer-events-none`.
- On phone widths, the welcome stacks copy/action above its abstract planes and filters remain before results in the existing normal layout. At `lg`, preserve the existing sidebar/results grid.
- Use a visible text action such as **Browse reviewed opportunities** targeting `#catalogue-results-heading`. Do not use icon-only controls.
- Long region names and welcome copy must wrap within the content panel. No decorative node may determine content height or block focus/clicks.

### `/programmes/[id]` focus

- Reuse the same catalogue-scoped static shell and abstract depth behind the heading plane.
- Preserve the factual status in the existing visible content plane and preserve `DiscoveryPreviewSlot` only where existing Phase 13 detail behavior already uses it; do not introduce it into the welcome.
- Facts/sources remain before sidebar verification/choice actions, with no decorative visual described as evidence.

## Visual Grammar

- **Color:** bright brand red only as controlled accent/plane; white and ink surfaces carry reading; silver/blush depth separates layers.
- **Shape:** offset rounded geometric planes, soft radial/linear CSS gradients, fine rule lines, and low-contrast dots/stripes created in CSS. No raster texture, campus silhouette, map, skyline, photo frame, or simulated video.
- **Motion:** static. Hover/focus state may use the existing native control color/focus feedback but no decorative animation, keyframe, delayed reveal, carousel, parallax, or timer-driven movement.
- **Contrast:** decorative values remain low-contrast behind solid white/ink reading planes; text and actions must pass existing readable style patterns.

## Automated Acceptance Matrix

| Scenario | Required assertion |
|----------|--------------------|
| Automatic arrival | One Visual welcome precedes filters/results for normal, no-media, empty, signed-out, and signed-in model states. |
| Media-free boundary | The welcome tree has no preview renderer, `img`, `video`, iframe, media path, external URL, playback prop, or new asset import. |
| Source-first separation | Welcome has no provider factual record/status/source/save/compare/official action; following cards retain all existing factual and choice controls. |
| Agency | Metro/pathway filters, result count, normal/qualification ordering, empty state, comparison/save, and official links remain unchanged. |
| Static atmosphere | Decorations are catalogue-scoped, `aria-hidden`, pointer-inert, overflow-safe, and static under normal and reduced-motion conditions. |
| Responsive/keyboard | Semantic heading/action, visible focus, long text, zero/one/many results, 320px/768px/desktop reflow, and no horizontal overflow. |
| Privacy | No API/store/profile/ranking/analytics/public-asset change or student-data prompt is introduced. |
| Phase independence | No plan, code, or evidence claims Phase 13 UAT completed. |

## Human UAT Release Checks

1. Open `/programmes` signed out and signed in. Confirm the Visual welcome appears before filters/results, contains no personal-data request, and its action reaches the factual result heading.
2. Inspect the welcome and detail atmosphere. Confirm all visual motifs are abstract, static, and cannot be read as a provider/campus photograph, map, media preview, or factual evidence.
3. At 320px, 768px, and desktop, tab through the welcome action, filters, source links, comparison/save, and official action. Confirm no clipped text or horizontal overflow.
4. Enable reduced motion. Confirm the same readable static welcome/atmosphere appears and no new media starts or loops. If existing reviewed local media appears on an unchanged detail/card path, confirm its previously bounded pause/visibility/reduced-motion behavior remains intact.
