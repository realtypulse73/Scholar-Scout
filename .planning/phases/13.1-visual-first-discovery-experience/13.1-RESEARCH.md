## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01:** Discovery opens with an **arrival panel**: a short visual welcome introduces a possible place, then hands the student to clean, source-first programme cards. Do not place the factual opportunity card, source state, comparison, or official action directly over the visual. — **Reversibility:** costly — this is the first-arrival composition across catalogue discovery and its responsive/UAT expectations.
- **D-02:** The visual layer appears automatically once discovery begins; it is not an optional visual-explorer destination. It must not require a sign-in, a completed student story, passive behavioural profiling, inferred attributes, or a change to catalogue ordering.
- **D-03:** When an opportunity has no approved visual, use a clearly labelled **Scholar Scout campus illustration** to preserve visual pull. The label must plainly state that it is a Scholar Scout illustration and not an official photograph of that provider campus.
- **D-04:** Preserve the previously locked fallback order: (1) approved local/provider/Scholar Scout visual; (2) Maps or Street View only after separate authorization; (3) visibly labelled Scholar Scout-generated illustration; (4) factual source-first fallback. Do not invent provider affiliation/evidence, use a third-party media path or embed, or treat copied Street View imagery as permission-free.
- **D-05:** Use local reviewed fixtures or safe illustrative fallback states so the visual-first journey is demonstrable during normal local UAT. A missing approved provider visual must still yield an honest, useful, visually intentional state.
- **D-06:** Apply a restrained visual atmosphere across catalogue discovery pages rather than only the arrival panel and provider detail. It may use low-contrast, CSS-only depth behind content but never background video or media autoplay. — **Reversibility:** costly — shared discovery shells, detail surfaces, responsive accessibility, and visual regression coverage depend on this presentation contract.
- **D-07:** Respect reduced-motion preferences by rendering the catalogue atmosphere static and disabling the existing narrow media-loop exception. The only allowed looping media remains the previously approved centered card: muted, pauseable, scroll/center bounded, and never active under reduced motion.

### the agent's Discretion
- Choose the exact visual motifs, copy, local illustrative assets, responsive layout, and CSS intensity, provided they keep text/action contrast high, stay visually calm, use no background media, and remain source-first.
- Reuse the governed public snapshot, renderable-media resolver, factual fallback, source/action, semantic controls, focus treatment, and motion-safe visual primitives instead of creating an alternate discovery data path.

### Deferred Ideas (OUT OF SCOPE)
- Recruiting students to upload campus or peer content needs separate consent, age/privacy, moderation, rights, takedown, attribution, and retention work.
- Individual student testimonials, outcome stories, and provider-linked personal narratives remain out of scope until their consent, factual, and non-affiliation rules are separately approved.
- A real Google Maps/Street View or another third-party renderer needs separate platform-terms, privacy, accessibility, and source-rights approval; screenshot copying is not approved.
- A visual system that changes the whole application outside catalogue discovery is a later design phase; this phase is intentionally bounded to the catalogue journey.

## Summary

Phase 13.1 should be a presentation-only extension of the Phase 13 public media projection: the `/programmes` server page already obtains a reviewed snapshot, builds `CatalogueDiscoveryModel`, and passes it to `CatalogueDiscoveryOverview`; learner components already receive only `renderableMedia`, never candidate evidence or embed URLs. [VERIFIED: codebase grep] The plan should replace the conditional “Optional visual explorer” with one normal-flow `Visual welcome` before the filters/results region, while retaining existing cards, filters, qualification order, save/compare, and official actions unchanged. [VERIFIED: `apps/web/components/catalogue/CatalogueDiscoveryOverview.tsx`]

The existing media boundary is the correct single source of truth. `resolveRenderableMedia` chooses an eligible `local-preview`, then an eligible Scholar Scout-owned `illustration`, and otherwise returns a factual fallback; approved embeds deliberately do not cross the learner projection. [VERIFIED: `apps/web/lib/catalogue-publication.ts`] `DiscoveryPreviewSlot` already provides local-only video/image rendering, factual fallback, provenance disclosure, non-affiliation copy, controlled playback, and Escape/focus-return behavior. [VERIFIED: `apps/web/components/catalogue/DiscoveryPreviewSlot.tsx`] Compose the new arrival from this seam without granting it a `playback` prop, so it cannot invoke `HTMLMediaElement.play()`.

No new library, service, API route, persistence field, or network-media flow is justified. [VERIFIED: Phase 13.1 CONTEXT.md and UI-SPEC.md] The major execution risk is fixture realism: production `public/` currently contains the generic `images/scholar-scout-transition-v1.png` and no reviewed `/media/*.mp4` or specific Scholar Scout illustration assets, while Phase 13 tests use only synthetic paths. [VERIFIED: codebase file inventory] A first implementation slice must therefore add rights-reviewed, local, committed assets (or explicitly select the factual fallback) and deterministic records/fixtures for all three acceptance states before visual UAT is claimed.

**Primary recommendation:** Implement a small arrival composition around the existing `DiscoveryPreviewSlot`, preserve the snapshot DTO/resolver unchanged, add static scoped CSS atmosphere to overview/detail, and first add deterministic checked-in local media/illustration/no-media fixtures with focused Jest and manual responsive evidence.

### Pattern 1: Keep media resolution outside the browser

**What:** Select renderable media in `resolveRenderableMedia` before publication and forward only the narrow `CatalogueRenderableMedia` DTO through `CatalogueDiscoveryItem`. [VERIFIED: `catalogue-publication.ts`, `catalogue-discovery.ts`]

**When to use:** For both the arrival and detail/factual-card presentation; never add a browser-side candidate, URL, or rights branch. [VERIFIED: UI-SPEC.md]

**Example:**

```typescript
// Source: apps/web/lib/catalogue-publication.ts
const local = reviewed.find((candidate) =>
  candidate.kind === 'local-preview' && isEligibleCandidate(candidate, now),
);
if (local) return { renderableMedia: toRenderableMedia(local), mediaFallback: false };
// Continue only to an eligible local Scholar Scout illustration; otherwise fail closed.
```

### Pattern 2: Compose arrival without media-card facts or autoplay

**What:** Give the arrival a semantic section and a destination heading; render `DiscoveryPreviewSlot` from the already-selected arrival media but do not provide a `playback` value. [VERIFIED: `DiscoveryPreviewSlot.tsx`, UI-SPEC.md]

**When to use:** Every reviewed `/programmes` snapshot, including one with zero visual items. [VERIFIED: UI-SPEC.md]

**Example:**

```tsx
// Source: prescribed composition based on existing component contract
<section aria-labelledby="visual-welcome-heading">
  <h2 id="visual-welcome-heading">Explore what learning could look like</h2>
  <DiscoveryPreviewSlot media={arrivalMedia} />
  <a href="#catalogue-results-heading">Browse reviewed opportunities</a>
</section>
```

The planner should choose `arrivalMedia` deterministically from the existing model without changing normal/qualification ordering or exposing a provider name in the media region. [VERIFIED: UI-SPEC.md]

### Pattern 3: Static, scoped atmosphere

**What:** Place `aria-hidden`, pointer-inert decoration inside an `overflow-hidden` shell with a positioned content plane and CSS-only gradients. [VERIFIED: `CatalogueFocusView.tsx`, `globals.css`, UI-SPEC.md]

**When to use:** The overview title/arrival shell and focus/detail shell only; do not alter global unrelated pages or reuse `StudentJourneyScene`, because its current implementation has a background image and animations that violate the phase’s CSS-only/static contract. [VERIFIED: `StudentJourneyScene.tsx`, `globals.css`, UI-SPEC.md]

### Anti-Patterns to Avoid

- **Browser-side media selection:** Never inspect raw candidates, `embedUrl`, or rights data from learner components; it duplicates the publication gate. [VERIFIED: `catalogue-publication.ts`, `catalogue-discovery.ts`]
- **Optional-only arrival:** Do not retain `visualItems.length > 0` as the gate for the first visual experience; that is the exact current behavior the phase replaces. [VERIFIED: `CatalogueDiscoveryOverview.tsx`, UI-SPEC.md]
- **Arrival playback:** Passing a playback object is what enables `video.play()` in `DiscoveryPreviewSlot`; the arrival must omit it. [VERIFIED: `DiscoveryPreviewSlot.tsx`]
- **Unscoped motion changes:** Do not globally remove `StudentJourneyScene` effects or unrelated transition-story animation; add catalogue-specific static rules. [VERIFIED: `globals.css`, UI-SPEC.md]

## Common Pitfalls

### Pitfall 1: Existing optional explorer prevents automatic arrival

**What goes wrong:** `CatalogueDiscoveryOverview` currently computes `visualItems` and renders the explorer only when its length is positive. [VERIFIED: `CatalogueDiscoveryOverview.tsx`]

**How to avoid:** Derive one deterministic arrival state for every reviewed snapshot and render the panel before the results layout; do not condition the panel on `/stories`, sign-in, or count of media-bearing cards. [VERIFIED: UI-SPEC.md]

### Pitfall 2: The fallback can become a misleading picture

**What goes wrong:** Existing illustration rendering displays a generic label but not the required exact “not an official photograph” disclaimer. [VERIFIED: `DiscoveryPreviewSlot.tsx`, `DiscoveryPreviewSlot.test.tsx`]

**How to avoid:** Add the exact visible illustration disclaimer at the arrival/composition layer (and preserve adjacent provenance/non-affiliation copy); preserve `DiscoveryPreviewSlot` factual fallback with no image-shaped empty frame. [VERIFIED: UI-SPEC.md]

### Pitfall 3: Reusing the preview component can accidentally authorize playback

**What goes wrong:** A supplied `playback` prop calls `video.play()` when `shouldPlay` is true. [VERIFIED: `DiscoveryPreviewSlot.tsx`]

**How to avoid:** The arrival never receives `playback`; retain the existing props only for factual cards and explicitly test no arrival video call to `play`. [VERIFIED: UI-SPEC.md]

### Pitfall 4: Current focus CSS animates and disappears under reduced motion

**What goes wrong:** `.catalogue-focus-decoration` uses a keyframe animation and reduced motion currently sets it to `opacity: 0`. [VERIFIED: `globals.css`]

**How to avoid:** Replace that decoration with a static low-contrast red/silver treatment, retaining a visible lower-contrast/silver surface under reduced motion. [VERIFIED: UI-SPEC.md]

### Pitfall 5: Test paths are not actual local-UAT assets

**What goes wrong:** Tests reference `/media/*.mp4` and `/images/scholarscout-workshop.png`, but the checked-in public inventory lacks those referenced assets. [VERIFIED: `apps/web/__tests__`, `apps/web/public` inventory]

**How to avoid:** Before asserting normal local UAT, add approved assets under `public/` and a deterministic reviewed snapshot fixture that exercises local preview, illustration, and no-media states; retain test-object fixtures for branch isolation. [VERIFIED: UI-SPEC.md]

### Pitfall 6: Layout/visual regression is not currently automated at target widths

**What goes wrong:** The current Jest/jsdom setup validates DOM contracts but does not measure 320px/768px layout or capture visual snapshots. [VERIFIED: `jest.config.ts`, test inventory]

**How to avoid:** Add structural width-safe assertions (`min-w-0`, shell overflow classes, responsive stacking classes) to Jest and make 320px, 768px, desktop, keyboard, and reduced-motion checks explicit human UAT/release evidence. [VERIFIED: UI-SPEC.md]
