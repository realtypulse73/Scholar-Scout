# Phase 13.1: Visual-First Discovery Experience — Media-Free Research

**Researched:** 2026-09-29
**Scope status:** Current planning source for the approved media-free release
**Confidence:** High — repository-first inspection

## Decision Summary

The first visual experience is an automatic, abstract, code-native welcome and catalogue-only atmosphere. It uses no visual media file, provider imagery, remote asset, embed, media resolver branch, student-data collection, or Phase 13 browser-UAT bridge. The result must send students quickly to the existing reviewed, source-first school/programme information and leave current student choice controls intact.

The prior local-media fixture proposal is superseded. Its historical evidence is retained in Git history, not in this active research contract.

## Verified Current State

| Area | Evidence | Planning consequence |
|------|----------|----------------------|
| Optional entry | `CatalogueDiscoveryOverview.tsx` computes `visualItems` and conditionally renders “Optional visual explorer.” | Replace the optional entry with one always-rendered `CatalogueVisualWelcome` before the existing catalogue grid. |
| Factual discovery | The overview already renders filters, result count, qualification order, cards, empty states, source-driven actions, and an anchorable results heading. | Preserve those regions and use an in-page welcome action to reach them. |
| Inherited media safety | The overview owns `VisualOpportunityCard`, `DiscoveryPreviewSlot`, an `IntersectionObserver`, manual pause state, and reduced-motion behavior for existing reviewed-local cards. | Do not remove, alter, or scan this legacy path as part of the welcome contract; retain it after the new welcome unchanged. |
| Detail composition | `CatalogueFocusView.tsx` contains the source-first detail page and an existing `catalogue-focus-decoration` seam. | Apply the same static catalogue shell language without changing facts, sources, compare/save, or official verification. |
| Style system | `globals.css` and Tailwind provide brand/silver/ink tokens, touch targets, focus treatment, and a reduced-motion query. | Add catalogue-scoped static depth only; no package, canvas, timer, keyframe, or global visual-system change. |
| Public data boundary | `catalogue-discovery.ts` exposes reviewed snapshot items, including a narrow existing `renderableMedia` field. | The welcome must not consume `renderableMedia`; it needs no new browser data or resolver path. |
| Test baseline | `CatalogueDiscoveryOverview`, `CatalogueFocusView`, and `DiscoveryPreviewSlot` each have focused Jest suites. | Add `CatalogueVisualWelcome.test.tsx` and narrow contract tests; retain existing media suites unchanged. |

## Architecture

```text
reviewed snapshot (unchanged)
        │
        ▼
CatalogueDiscoveryOverview
        ├── CatalogueVisualWelcome (new, abstract code-native component)
        │       └── in-page anchor to factual results
        ├── existing filters/results/cards (unchanged factual authority)
        └── existing optional reviewed-local card-media controller (preserved, not widened)

CatalogueFocusView
        └── same static catalogue-only CSS shell behind existing factual detail
```

## Required Boundaries

- No new file in `apps/web/public/images` or `apps/web/public/media`.
- No `<img>`, `<video>`, iframe, embed, remote URL, raster asset, or `DiscoveryPreviewSlot` use in `CatalogueVisualWelcome`.
- No visual motif may name, depict, or imply a provider/campus/student scene, affiliation, evidence, or factual claim.
- No API route, server store, account/profile input, consent prompt, analytics event, ranking input, provider-data edit, or persistence change.
- No autoplay, loop, timer-driven visual effect, or expansion of the existing centre-card exception.
- Phase 13 browser UAT remains independently outstanding and cannot be claimed by this phase.

## CSS and Accessibility Pattern

Use a `catalogue-visual-shell` and `catalogue-visual-welcome` with low-contrast red/silver CSS planes, gradients, rules, and abstract shapes. Each decorative node is `aria-hidden` and pointer-inert; solid content planes hold all readable copy and action controls. The UI is static in normal and `prefers-reduced-motion` states. The welcome gets a semantic heading and visible text action; it must wrap long copy and preserve the existing 44px target/focus patterns.

## Validation Strategy

| Behavior | Test evidence |
|----------|---------------|
| Automatic media-free welcome | Overview DOM test covers normal, media-bearing, no-media, and empty models, with welcome before filters/results. |
| Dedicated no-media contract | `CatalogueVisualWelcome.test.tsx` and its scoped source/render contract prove no renderer, asset path, playback, external URL, or data-collection surface. |
| Factual preservation | Existing overview/focus tests retain count, filters, ordering, empty state, source/status, compare/save, and official verification actions. |
| Static visual shell | Overview/focus DOM/CSS assertions cover hidden/inert decoration, readable plane, local overflow protection, and reduced-motion static behavior. |
| Human verification | Browser checks at 320px, 768px, and desktop validate reflow, keyboard traversal, visual abstraction, source-first clarity, and reduced-motion state. |
| Scope proof | Diff review confirms no public asset, API, store, profile, analytics, ranking, provider, or Phase 13-status change. |

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Visual polish becomes provider imagery or an implicit factual claim | Restrict visual language to abstract code-native shapes; keep source/fact actions outside the welcome. |
| Welcome removes existing bounded media safety behavior | Preserve the legacy card grid/controller after the welcome; test the new component independently. |
| A contract test rejects inherited safe media behavior | Scan/test only `CatalogueVisualWelcome`, not the overview that legitimately hosts the existing exception. |
| Reduced motion or narrow screens hide necessary content | Static CSS, readable content plane, `min-w-0`/overflow-safe patterns, and browser-width checks. |
| Visual-first becomes data collection | No input, consent, API, store, profile, analytics, or ranking scope is allowed. |

## Environment and Dependencies

No installation, package, registry, external documentation, image-generation tool, external network request, or asset download is needed. Use the existing Next.js/React/TypeScript/Tailwind/Jest stack and Corepack-pinned pnpm commands.
