<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| domain operation -> adapter | Trusted server code supplies an opaque expected version and receives applied/conflict/unavailable. |
| web adapter -> HTTP data service | Authenticated service calls carry ETag preconditions; callers cannot forge app-owned persistence authority. |
| web adapter -> Vercel Blob | Private provider credentials and ETags remain server-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-01 | Tampering | concurrent adapter writes | high | mitigate | Provider-level CAS plus interleaved winner/loser tests for all adapters. |
| T-04-02 | Information Disclosure | conflict responses | high | mitigate | Keep provider versions internal and retain authorized programme-safe response fields only. |
| T-04-03 | Denial of Service | conflict retries | medium | mitigate | Programme replacements never retry automatically. |
| T-04-04 | Spoofing | HTTP conditional headers | high | mitigate | Preserve service bearer authentication and validate the current strong ETag server-side. |
| T-04-SC | Tampering | package installs | high | mitigate | No package install; use pinned dependencies already audited in research. |
</threat_model>
